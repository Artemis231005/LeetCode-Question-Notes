# LeetCode 15 — 3Sum

## Metadata

* **LeetCode:** 15
* **Problem:** 3Sum
* **Difficulty:** Medium
* **Topics:** Array, Two Pointers, Sorting
* **Pattern:** Sort + Fix One Element + Two Pointers
* **Key Technique:** Sort the array, fix each element as the "first" of the triplet, then use two pointers on the remaining sorted range to find pairs summing to its negation — skipping duplicates at every level
* **Optimal Complexity:** `O(n²)` Time, `O(1)` Auxiliary Space (excluding the output)

---

## Problem Statement

Given an integer array `nums`, return all unique triplets `[nums[i], nums[j], nums[k]]` such that `i != j != k` and `nums[i] + nums[j] + nums[k] == 0`. The solution set must not contain duplicate triplets.

---

## Approaches

1. **Brute Force — Check Every Triplet with a Hash Set for Deduplication**
2. **Optimal — Sort + Fix One Element + Two Pointers**

---

# Approach 1 — Brute Force / Check Every Triplet with a Hash Set for Deduplication

## Idea

Check every possible triplet `(i, j, k)` directly. Whenever three values sum to zero, sort that triplet and insert it into a hash set of triplets to automatically avoid duplicates in the final answer.

## Dry Run

```text
nums = [-1, 0, 1, 2, -1, -4]
```

Check triplet `(-1, 0, 1)` (indices 0,1,2):

```text
-1 + 0 + 1 = 0 → valid → sorted triplet [-1,0,1] → add to set
```

Check triplet `(-1, 2, -1)` (indices 0,3,4):

```text
-1 + 2 + (-1) = 0 → valid → sorted triplet [-1,-1,2] → add to set
```

Check triplet `(0, 1, -1)` (indices 1,2,4):

```text
0 + 1 + (-1) = 0 → valid → sorted triplet [-1,0,1] → already in set, skip
```

Continue through all remaining triplets the same way.

Final unique triplets: `[-1,0,1]` and `[-1,-1,2]`.

## Algorithm

1. Initialize an empty hash set of triplets (e.g. using sorted tuples or a set of vectors).
2. For each `i` from `0` to `n-3`:
3. For each `j` from `i+1` to `n-2`:
4. For each `k` from `j+1` to `n-1`:

   * If `nums[i] + nums[j] + nums[k] == 0`, sort the triplet and insert it into the set.
5. Return the set's contents as a list.

## Complexity

* **Time:** `O(n³)`

  * Three nested loops check every possible triplet directly.
* **Space:** `O(n)` (beyond the output)

  * For the hash set used to deduplicate triplets.

## Notes / Tips

* Checking every triplet is the most naive approach possible — sorting the array first (as in Approach 2) both speeds up the search and makes duplicate-skipping far simpler and cheaper than hashing entire triplets.
* The hash-set-of-sorted-triplets deduplication trick works but adds overhead (sorting each found triplet, hashing a vector) that a sorted-array + pointer-skipping approach avoids entirely.

## Code

```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        int n = nums.size();
        set<vector<int>> uniqueTriplets;

        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                for (int k = j + 1; k < n; k++) {
                    if (nums[i] + nums[j] + nums[k] == 0) {
                        vector<int> triplet = {nums[i], nums[j], nums[k]};
                        sort(triplet.begin(), triplet.end());
                        uniqueTriplets.insert(triplet);
                    }
                }
            }
        }

        return vector<vector<int>>(uniqueTriplets.begin(), uniqueTriplets.end());
    }
};
```

# Approach 2 — Optimal / Sort + Fix One Element + Two Pointers

## Idea

Sort the array first. Fix each element `nums[i]` as the smallest element of a candidate triplet, then use two pointers (`left` starting right after `i`, `right` at the end) to search for a pair summing to `-nums[i]` within the remaining sorted subarray — moving `left` right or `right` left based on whether the current sum is too small or too large. Skip over duplicate values at every level (`i`, `left`, `right`) to avoid duplicate triplets without needing a hash set.

## Dry Run

```text
nums = [-4, -1, -1, 0, 1, 2]  (already sorted)
```

`i = 0` (value `-4`), target for pair = `4`:

```text
left=1 (-1), right=5 (2): sum = -1+2 = 1 < 4 → move left right
left=2 (-1), right=5 (2): sum = -1+2 = 1 < 4 → move left right
left=3 (0), right=5 (2): sum = 0+2 = 2 < 4 → move left right
left=4 (1), right=5 (2): sum = 1+2 = 3 < 4 → move left right
left=5, right=5: left == right, stop
```

No triplet found for `i=0`.

`i = 1` (value `-1`), target for pair = `1`:

```text
left=2 (-1), right=5 (2): sum = -1+2 = 1 == 1 → found triplet [-1,-1,2]
   move left right, right left → left=3, right=4
left=3 (0), right=4 (1): sum = 0+1 = 1 == 1 → found triplet [-1,0,1]
   move left right, right left → left=4, right=3 → left > right, stop
```

`i = 2` (value `-1`): same as `nums[1] = -1` → skip (duplicate first element).

`i = 3` (value `0`), target for pair = `0`:

```text
left=4 (1), right=5 (2): sum = 1+2 = 3 > 0 → move right left
left=4, right=4: left == right, stop
```

No triplet found for `i=3`.

Final triplets: `[-1,-1,2]` and `[-1,0,1]`.

## Algorithm

1. Sort `nums` in ascending order.
2. For each `i` from `0` to `n-3`:

   * If `i > 0` and `nums[i] == nums[i-1]`, skip (avoids duplicate first elements).
   * If `nums[i] > 0`, break early (no triplet summing to zero is possible past this point, since all remaining values are non-negative or positive).
   * Set `left = i + 1`, `right = n - 1`.
   * While `left < right`:

     * `sum = nums[i] + nums[left] + nums[right]`.
     * If `sum == 0`: record the triplet, then skip duplicates by advancing `left` while `nums[left] == nums[left+1]` and `right` while `nums[right] == nums[right-1]`, then move both pointers inward once more.
     * If `sum < 0`: increment `left` (need a larger sum).
     * If `sum > 0`: decrement `right` (need a smaller sum).
3. Return the list of triplets found.

## Complexity

* **Time:** `O(n²)`

  * Sorting is `O(n log n)`; the outer loop runs `O(n)` times, and each iteration's two-pointer scan is `O(n)`.
* **Space:** `O(1)` auxiliary (beyond the output and sort's own space)

  * No hash set needed — duplicate avoidance is done directly through sorted-array skipping.

## Notes / Tips

* Sorting first is what enables both the two-pointer technique (which needs monotonic order to know which direction to move) and cheap duplicate-skipping (adjacent equal values are guaranteed to be next to each other after sorting).
* The early `break` when `nums[i] > 0` is a valid optimization, not just a skip — since the array is sorted, if the smallest fixed element is already positive, no combination of it with two later (equal or larger) values can sum to zero.
* This is the standard template for "k-sum" problems: fix `k-2` elements via nested loops (or recursion for general `k`), then finish the last two with a two-pointer scan — LC 18 (4Sum) builds directly on this same idea with one more fixed loop.

## Code

```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        vector<vector<int>> result;
        int n = nums.size();

        for (int i = 0; i < n - 2; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }
            if (nums[i] > 0) {
                break;
            }

            int left = i + 1, right = n - 1;

            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];

                if (sum == 0) {
                    result.push_back({nums[i], nums[left], nums[right]});

                    while (left < right && nums[left] == nums[left + 1]) left++;
                    while (left < right && nums[right] == nums[right - 1]) right--;

                    left++;
                    right--;
                } else if (sum < 0) {
                    left++;
                } else {
                    right--;
                }
            }
        }

        return result;
    }
};
```
