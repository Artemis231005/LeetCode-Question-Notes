# LeetCode 38 — Count and Say

## Metadata

* **LeetCode:** 38
* **Problem:** Count and Say
* **Difficulty:** Medium
* **Topics:** String, Recursion, Simulation
* **Pattern:** Run-Length Encoding Simulation
* **Key Technique:** Build each term by run-length-encoding the previous term — scan for consecutive equal digits, appending count + digit as you go
* **Optimal Complexity:** `O(2^n)` Time (string length grows exponentially), `O(2^n)` Space

---

## Problem Statement

The "count-and-say" sequence is defined recursively: `countAndSay(1) = "1"`, and each subsequent term is generated by describing the digits of the previous term as runs of consecutive equal digits (e.g. `"1211"` reads as "one 1, one 2, two 1s" → `"111221"`). Given `n`, return the `n`th term.

---

## Approaches

1. **Brute Force — Manual Run Detection with Nested Comparisons**
2. **Optimal — Single-Pass Run-Length Encoding**

---

# Approach 1 — Brute Force / Manual Run Detection with Nested Comparisons

## Idea

For each term, build the next one by scanning character by character. For each new run detected, use a separate inner loop to count how far the run extends, comparing each character against the starting character of the run before advancing.

## Dry Run

```text
prev = "1211"
```

Position `0`:

```text
char = '1', scan ahead: index 1 is '2' (different) → run length 1
append "1" + "1" = "11"
```

Position `1`:

```text
char = '2', scan ahead: index 2 is '1' (different) → run length 1
append "1" + "2" = "12"
```

Position `2`:

```text
char = '1', scan ahead: index 3 is '1' (same), index 4 is out of bounds → run length 2
append "2" + "1" = "21"
```

Combine:

```text
"11" + "12" + "21" = "111221"
```

## Algorithm

1. Start with `result = "1"`.
2. Repeat `n - 1` times:

   * Build the `next` string from `result`.
   * For each position `i` in `result` not yet processed:

     * Count how many consecutive characters starting at `i` match `result[i]` using an inner loop.
     * Append the count and the character to `next`.
     * Advance `i` past the run.
   * Set `result = next`.
3. Return `result`.

## Complexity

* **Time:** `O(2^n)`

  * The string length roughly grows by a factor close to `1.3` each term, but is treated as exponential in the worst case; each term requires a full scan of the previous term.
* **Space:** `O(2^n)`

  * For storing the growing string across terms.

## Notes / Tips

* The two-loop structure (outer scan + inner run-counting loop) is functionally the same as a single-pass approach — it's included here mainly as a more literal/explicit version of "detect runs" before collapsing it into one pass.
* String length growth is inherent to the problem itself — no approach can avoid the exponential blowup, only the per-term construction cost can be optimized.

## Code

```cpp
class Solution {
public:
    string countAndSay(int n) {
        string result = "1";

        for (int level = 1; level < n; level++) {
            string next = "";
            int i = 0;

            while (i < result.size()) {
                char digit = result[i];
                int count = 0;

                int j = i;
                while (j < result.size() && result[j] == digit) {
                    count++;
                    j++;
                }

                next += to_string(count) + digit;
                i = j;
            }

            result = next;
        }

        return result;
    }
};
```

# Approach 2 — Optimal / Single-Pass Run-Length Encoding

## Idea

Same run-length encoding idea, but streamlined into a single forward pass per term using one pointer and a running count, incrementing the count while the next character matches, and flushing (appending count + digit) the moment it doesn't.

## Dry Run

```text
prev = "1211"
```

Process:

```text
i=0: digit='1', count=1
i=1: result[1]='2' != '1' → flush "1"+"1"="11", reset count=1, digit='2'
i=2: result[2]='1' != '2' → flush "1"+"2"="12", reset count=1, digit='1'
i=3: result[3]='1' == '1' → count=2
end of string → flush "2"+"1"="21"
```

Combine flushes:

```text
"11" + "12" + "21" = "111221"
```

## Algorithm

1. Start with `result = "1"`.
2. Repeat `n - 1` times:

   * Initialize `next = ""`, `count = 1`.
   * For `i` from `1` to `result.size()`:

     * If `i < result.size()` and `result[i] == result[i-1]`, increment `count`.
     * Otherwise, append `count` and `result[i-1]` to `next`, then reset `count = 1`.
   * Set `result = next`.
3. Return `result`.

## Complexity

* **Time:** `O(2^n)`

  * Same growth as Approach 1 — the exponential string length is unavoidable, but each term is now built in exactly one pass instead of a nested loop structure.
* **Space:** `O(2^n)`

  * For storing the growing string across terms — this is the true bottleneck of the problem, not the construction technique.

## Notes / Tips

* Iterating `i` up to and including `result.size()` (one past the last valid index) with a bounds check is what lets the final run get flushed without needing a separate statement after the loop.
* This is the standard run-length-encoding template — same shape as compressing any string of repeated characters (e.g. "String Compression", LC 443).
* Given `n`'s constraints are typically small (`<= 30`), the exponential blowup stays manageable in practice, even though the algorithm's complexity is technically exponential in `n`.

## Code

```cpp
class Solution {
public:
    string countAndSay(int n) {
        string result = "1";

        for (int level = 1; level < n; level++) {
            string next = "";
            int count = 1;

            for (int i = 1; i <= result.size(); i++) {
                if (i < result.size() && result[i] == result[i - 1]) {
                    count++;
                } else {
                    next += to_string(count) + result[i - 1];
                    count = 1;
                }
            }

            result = next;
        }

        return result;
    }
};
```
